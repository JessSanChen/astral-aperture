# Tests that protect B1's meaning

Acceptance targets for the implementation, not tests that exist yet.

| Test | Failure it should catch |
|---|---|
| Oracle perturbation | Hidden truth changes while visible evidence is unchanged; controller input must not change |
| Allowed-view serialization | Unexpected fields, privileged metadata, or environment objects enter the controller input |
| Unselected branch isolation | A controller can read another action's cached output |
| Forbidden evaluator access | The controller process can reach evaluator files, credentials, or unrestricted network tools |
| Grouped split integrity | Same base world or near-duplicate renderings cross train and held-out groups |
| Metadata leakage | Family names, paths, scenario IDs, or order encode outcomes |
| Identity mismatch | Provider, model, or config changes without a new arm or an explicit failure |
| Sample/cache semantics | Repeated independent calls collapse into one cached response |
| Resume equivalence | Interrupted or resumed aggregation duplicates, drops, or changes accepted records |
| Failure accounting | Timeout, parse failure, refusal, or retry disappears from denominators |
| Decision lock | Oracle feedback changes a stored pre-audit decision |
| Full-inspection parity | The comparator is denied information the new method receives |
| Fresh-clone report | The report needs undeclared local files, credentials, or live model calls |

Development agents may use development labels. Final holdout labels, instances, and
response banks live outside their accounts and mounts. Restrict actual users, mounts,
credentials, and service interfaces; a directory name or an AGENTS.md rule is not
access control. With a single researcher, a separate evaluation account and a
recorded freeze reduce accidental exposure but do not make evaluation fully blind.
